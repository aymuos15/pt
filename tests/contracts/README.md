# WP00 synthetic protocol contracts

These tests define/assert ledger consistency, **not PT conformance, a production
validator, a real-pytest oracle, or a benchmark**. No project tests, artifact bytes,
installed environment, or source snapshot are verified. All example hashes and
verification flags are synthetic placeholders. `validate_trace` always returns
`qualified: false` and explicitly false external-evidence checks.

- `protocol_examples.py`: hand-constructed scenarios and final records, not
  generated by the checker. They preserve duplicate Unicode node IDs, selection
  order/deselection, collection failures/partial inventory, phase failures,
  xfail/xpass, retry history, fail-fast, collect-only/no-tests, artifacts,
  cancellation, crashes, and generation/environment uncertainty.
- `protocol_contract.py`: test-only decoded-ledger checker and local schema
  registry. It checks identities, per-producer order, collection/selection
  partitions, attempts/phases, artifact assertions, terminal arithmetic, and
  necessary completion gates. Unsupported adapters/resources fail closed.
- `test_protocol_contract.py`: valid scenarios plus omission/corruption mutations,
  causal interleaving, first-stop precedence, and bounded-ledger checks.
- `test_final_result.py`: independent schema tests, all ten typed terminal
  outcomes (including a schema-only recovery example), exact documented pytest
  exit mapping, and rejection of false completion claims.
- `test_wp00_review.py`: documentation/pin traceability guards for the authored
  acceptance review, all permissions/outcomes/invariants/threats/ADRs, remaining
  gates and links. These check record consistency, not semantic review quality,
  implementation, security, qualified support or campaign acceptance.
- `../../bench/harness/tests/test_protocol_draft.py`: per-message schema/examples,
  all 32 kinds, producer roles and exact target handshake; kept separate from
  the contract ledger suite.

From the repository root, using the harness's locked development dependencies:

```sh
uv run --locked --project bench/harness --python 3.12.12 python -W error::ResourceWarning -m unittest discover -s tests/contracts -v
uv run --locked --project bench/harness --python 3.12.12 python -W error::ResourceWarning -m unittest discover -s bench/harness/tests
```

See [the protocol contract](../../docs/protocol-draft.md) for precise arithmetic,
ordering, bounds and limitations. These suites do not parse wire frames, prove
producer honesty, establish syscall/process ownership, or measure overhead.
Normalized duplicate-free events are inputs; a production transport's identical
redelivery handling remains unimplemented. The final-result schema can express
only necessary conditions, not occurrence arithmetic or external truth.

## Development failures retained

The initial cross-product test found that the example factory claimed artifact
failure even with no requested artifact; expectations now distinguish required
and absent artifacts. Further mutations exposed checker gaps for internal/usage
errors with backend zero, abandoned attempts hidden behind exit 1, unresolved
retries, unsupported not-run reasons, early generation checks, and a worker
record after prelaunch rejection. Regression tests now cover those paths. No
failed corpus or timing sample was removed or reclassified by these fixes.

A later full-harness rerun failed in its existing descendant-cleanup test when
`/proc/<pid>/stat` vanished during the read (`ProcessLookupError`/ESRCH). The test
already treated ENOENT as process disappearance; it now handles ESRCH as well,
with a deterministic regression check that permission errors still propagate.
The PID/start-time ownership comparison and live-child assertion are unchanged;
no production cleanup behavior or benchmark exclusion rule was relaxed.
