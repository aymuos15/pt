# Bridge protocol v0 — draft

Status: proposed, unimplemented, unreviewed. This is a design boundary, not a
promise of a stable wire format.

The [baseline decision](baseline-contract-v1.md) selects a private inherited
Unix socket pair, strict version matching, ownership, and bounded failure rules.
The event catalog below remains incomplete and requires versioned extension.

Each execution session owns a dedicated local channel, separate from test
stdout and stderr. Frames consist of a 32-bit unsigned big-endian payload length
followed by that many bytes of UTF-8 JSON. The receiver rejects zero-length,
truncated, invalid UTF-8, invalid JSON, or oversized frames. The proposed maximum
payload is 1 MiB; larger output and artifacts use separately bounded streams or
references. Never deserialize pickle or invoke code from a message.

Each message contains `protocol_version` (integer, initially 0), `run_id`,
`generation_id`, `session_id`, `producer_id`, `sequence` (nonnegative integer),
`kind`, and an object `payload`. IDs are opaque strings generated by trusted
owners, never project-controlled filenames. Sequence numbers start at zero and
increase by one per producer and session; missing or conflicting events make the
run incomplete. A duplicate with identical identity and contents may be
deduplicated; it is not evidence of exactly-once execution.

Kinds must cover lifecycle, collection and item occurrence inventory, phase
reports, warnings, capability decisions, artifacts, failure, and terminal status.
Their exact schemas and negotiation rules are unresolved. A terminal event is
not alone sufficient for success: the coordinator must validate accounting,
generation, artifacts, process exit, and required cleanup. EOF without a valid
terminal record is infrastructure failure. The transport must authenticate or
restrict access to the owning user as appropriate to the platform, and handle
backpressure without unbounded buffering. Test-created descendants must not be
able to keep a session falsely alive indefinitely.

`protocol-v0.schema.json` proposes a **subset** of per-message payload shapes for
session start, item occurrences, phase reports, collection errors, and session
termination. It is not a complete event set or a wire implementation. Duplicate
node IDs are valid when occurrence ordinals differ. Schema validation alone cannot
verify frame size in bytes, unique/ordered ordinals, producer sequence continuity,
cross-message accounting, authentication, artifacts, or completion. A valid
terminal message is not a successful final result. Tests currently exercise only
the draft schema, not a bridge or coordinator.

Open decisions include channel implementation, handshake and version negotiation,
schema evolution, precise identity grammar, artifact authentication, and
platform-specific ownership and cleanup. No implementation should treat this
draft as evidence of a complete threat model or protocol conformance.
